Problem#

Thought i’d share the mental process behind how solving small everyday problem leads to the reinvention of a design principle that is well established in the industry.

While designing a system for my work, i realised the data i was going to receive will be quite sensitive. The system was written to work either locally for testing and development or in the cloud for production. If it was only former, i wouldn’t worry: i am the only one who has access to the device and data. Cloud, however, is another thing. While of course i can and will use encryption at rest, the security model of cloud-deployment is still boils down to the identity and access management: if anyone somehow gets hands on validate account, that encryption will not help. So i became uneasy and decided to additionally safeguard data. “Additional encryption!” i thought, creating a nice pyramid of platform (cloud), application (system) and data (yet-to-be written encryption).

Design#

XOR and symmetric encryption#

My first thought that usually works for malware obfuscation was to throw a quick and dirty XOR. Right after i realized that the encryption key would have to be inside the application which, according to my security model, can be considered compromised and the key retrieved. Plus, the app is not a malware, so my usual safeguards against reverse-engineering were not applicable. So the problem becomes not ‘how to protect the data’ but ‘how to protect the encryption key’.

RSA and assymetric encryption#

Alright, if the key is the issue, why not bypass it with assymetry and RSA? Generate a pair, leave private key at home to have exclusive access to decryption and embed the public key in the app for encryption. Something PGP like. Should be simple enough.

Almost got my hands on the keyboard when i realized RSA is quite limited in terms of plaintext size depending on the key length. Definetly not enough for the type of data i needed to process. Trying to solve that would be to chunk data akin to block-cyphers, encrypt it, hardcode or have some kind of service information concatenated with cyphertext and reverse everything during decryption. Sounded doable, but overly complicated and brittle for the task at hand.

Envelope and hybrid encryption#

“Why not combine the two?” i thought then. I don’t need to process the whole plaintext. I can just solve my key problem and then use the symmetric crypto to safeguard the rest of data. It clicked!

While we’re at it, we can quickly jump from XOR skipping RC4 straight to AES. Being a fancy, we can even indulge ourselves with AES-GCM for added data authenticity.

Now let’s add the encrypted RSA part that will secure the key:

from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.asymmetric import padding, rsa

class Enveloper:
  def __init__(self, rsa_public_key_path):
    self.aes_key = AESGCM.generate_key(bit_length=256)
    self.aesgcm = AESGCM(self.key)

    with open(rsa_public_key_path, "rb") as f:
      self.rsa_key = serialization.load_pem_public_key(f.read())
    
    self.enc_aes_key = self.rsa_key.encrypt(self.aes_key, 
      padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None,
      ),
    )
    
def encrypt(plaintext):
    nonce = os.urandom(12)
    ciphertext = aesgcm.encrypt(nonce, plaintext, None)
    return nonce + ciphertext
